An unbounded reader is a denial-of-service vector you built yourself. It is easy to miss because the failure mode is not an error but a slow, quiet degradation: one oversized response, one server that never closes the connection, one redirect loop that keeps a worker busy until something upstream gives up first.

The remedy is unglamorous. Give the reader a byte budget and a time budget, enforce both while the body is still streaming, and make the resulting failure a value the caller must handle rather than an exception that propagates until someone catches it generically.

Metadata deserves the same discipline. A page that declares no title, no canonical URL, and no publication date is not an error condition; it is the ordinary case. Precedence rules should be written down, tested, and boring, so that the reader degrades to a hostname and a heading instead of refusing to store anything at all.
