Bounded Fetching for Knowledge Systems

By Dana Okonkwo

A knowledge system that reads the open web inherits every hazard of the open web. The fetcher is the boundary, and a boundary that is not enforced in one place is not enforced at all. Every limit worth having — protocol, target, redirect depth, timeout, media type, response size — belongs to a single owning module with constants that tests can assert directly.

Why redirects deserve their own budget

Redirects are the most common way a safe-looking request becomes an unsafe one. The initial hostname resolves to a public address, the operator sees a familiar domain, and three hops later the request lands on a metadata endpoint inside the network. Revalidating only the first URL is the same as not validating at all, so each hop is treated as a fresh request with a fresh resolution and a fresh policy check.

Size limits are a streaming concern

A declared Content-Length is a claim, not a fact. The only reliable cap counts bytes as they arrive and aborts the moment the budget is exhausted, which keeps a hostile or merely careless server from exhausting memory on the reader's side.

Treat the network as adversarial and the parser as fallible.

  • Resolve immediately before connecting.
  • Refuse credentials embedded in URLs.
  • Return typed failures, never raw response bodies.
